Learn Terraform from a network engineering perspective. Start with the AWS provider and Terraform lifecycle, then build Route 53 infrastructure and generate reusable Terraform configuration.

The goal is to understand the Terraform workflow before moving into larger AWS networking resources such as VPCs, subnets, route tables, security groups, NAT gateways, Transit Gateway, and VPN.

01
Terraform Setup Understand what Terraform is, how the CLI works, the basic configuration structure, and how it fits into infrastructure automation.
02
AWS Provider Learn where the AWS provider sits between Terraform configuration and AWS infrastructure, and how provider configuration works.
03
Terraform Lifecycle Follow the workflow from terraform init through validate, plan, apply, state management, change, and destroy.
04
AWS Route 53 Lab Learn how Terraform represents a Route 53 hosted zone, DNS records, domains, and subdomains using a practical AWS example.
05
Terraform Generator Enter Route 53 variables and automatically generate Terraform HCL, Terraform JSON, and a portable YAML specification.

Current Generator Support

The first generator release focuses on AWS Route 53. 

AWS Route 53
│
├── Hosted Zone
│
├── Record Name
│
├── Record Type
│   ├── A
│   ├── AAAA
│   ├── CNAME
│   └── TXT
│
├── Record Value
│
├── TTL
│
└── AWS Region

The same input is validated and then rendered into HCL, Terraform-compatible JSON, and the portal's YAML specification.

Generated Formats

Terraform HCL

Standard Terraform configuration written to a file such as: 

main.tf

Terraform JSON

Terraform also supports configuration expressed using its JSON syntax. 

main.tf.json

YAML Specification

YAML is used by this portal as a portable configuration representation. Terraform does not directly execute this YAML file. 

config.yaml
KNOWLEDGE-SHARING MODE

No AWS Credentials Required

The current Terraform portal is designed for learning, documentation, and configuration generation. 

Portal
   |
   +--> Does NOT store AWS credentials
   |
   +--> Does NOT call AWS APIs
   |
   +--> Does NOT run terraform apply
   |
   +--> Does NOT run terraform destroy
   |
   `--> Generates configuration for engineer review

This keeps configuration generation separate from infrastructure execution.
