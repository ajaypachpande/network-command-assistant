Terraform AWS Provider

Learn where the AWS Provider sits between Terraform and AWS, why Terraform needs a provider, and how Terraform configuration is translated into AWS infrastructure operations.

Learning Objective

After this section, you should understand the relationship between Terraform Core, the HashiCorp AWS Provider, AWS APIs, and AWS resources.

What is the AWS Provider?

Terraform Core manages configuration, dependencies, state, planning, and the resource lifecycle.

Terraform Core does not directly know how to create AWS-specific resources.

The AWS Provider adds the AWS-specific knowledge that Terraform needs to communicate with AWS services.

Step 1: versions.tf

The required_providers block tells Terraform which provider plugin the configuration requires.

versions.tf 
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = ">= 5.0"
    }
  }
}

In simple terms: 

required_providers
        │
        ▼
Which provider do I need?
        │
        ▼
hashicorp/aws

Step 2: provider.tf

The provider block configures how the AWS Provider should operate.

provider.tf 
provider "aws" {
  region = var.aws_region
}

The important distinction is: 

versions.tf
     │
     ▼
WHICH provider?
     │
     ▼
hashicorp/aws


provider.tf
     │
     ▼
HOW should the provider operate?
     │
     ▼
AWS configuration

Step 3: terraform init

Terraform initialization prepares the working directory and installs the providers required by the configuration.

COMMAND 
terraform init
WHAT HAPPENS 
terraform init
      │
      ▼
Read Terraform configuration
      │
      ▼
Find required_providers
      │
      ▼
Identify hashicorp/aws
      │
      ▼
Resolve/install provider
      │
      ▼
Initialize working directory
      │
      ▼
Ready for validate / plan

Provider vs Resource

PROVIDER 
provider "aws" {
  region = var.aws_region
}

This configures the AWS Provider.

RESOURCE 
resource "aws_route53_zone" "primary" {
  name = var.domain_name
}

This describes an AWS resource Terraform should manage. 

provider "aws"
      │
      │ enables AWS communication
      ▼
aws_route53_zone
      │
      │ represents infrastructure
      ▼
Route 53 Hosted Zone

Authentication Concept

A real Terraform execution needs an authorized AWS identity before the AWS Provider can perform AWS API operations.

Authentication information should remain outside the Terraform configuration that is stored in source control.

Security Rule

Never place AWS access keys, secret keys, passwords, or session tokens inside Terraform files committed to Git.

Key Takeaway

Terraform Core decides what needs to happen. The AWS Provider understands how Terraform resources relate to AWS services and communicates with AWS APIs.
