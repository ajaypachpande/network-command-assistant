Site-to-Site IPsec VPN Troubleshooting

Follow the tunnel from Phase 1 through Phase 2, routing, policy, sessions, and packet flow.

FortiGate Palo Alto

FortiGate IPsec VPN

1. Check overall tunnel status

SAFE 
get vpn ipsec tunnel summary

What it does

Provides a quick summary of IPsec tunnels and Phase 2 selector state.

What to look for

  • Expected tunnel name.
  • Selectors showing as up.
  • RX and TX counters increasing when traffic is generated.

Decision

If the tunnel or selectors are down, continue to Phase 1 and Phase 2 checks.

If the tunnel is up but traffic does not pass, jump to routing, firewall policy, session, and packet capture checks.

2. Check IKE / Phase 1

SAFE 
diagnose vpn ike gateway list

What it does

Displays IKE gateway and Phase 1 security association information.

What to look for

  • Correct tunnel or gateway name.
  • Correct remote peer IP.
  • IKE version.
  • Established IKE security association.

If Phase 1 is down

  • Verify peer reachability.
  • Verify UDP 500 and UDP 4500 are not blocked.
  • Compare pre-shared key or certificate configuration.
  • Compare IKE version.
  • Compare encryption algorithm.
  • Compare authentication algorithm.
  • Compare Diffie-Hellman group.

3. Check Phase 2 / IPsec SA

SAFE 
diagnose vpn tunnel list

What it does

Displays IPsec tunnel and security association details.

What to look for

  • Correct Phase 2 selectors.
  • Local and remote protected subnets.
  • Encryption and authentication parameters.
  • Packet counters.

If Phase 1 is up but Phase 2 is down

  • Compare local and remote selectors.
  • Check Phase 2 encryption settings.
  • Check PFS configuration.
  • Check lifetime settings if negotiation repeatedly fails.

4. Check routing

SAFE 
get router info routing-table all

What to look for

Confirm the remote VPN subnet resolves toward the expected IPsec tunnel or appropriate next hop.

Also verify the return route exists on the remote side.

5. Check firewall policy and NAT

SAFE 
show firewall policy

What to verify

  • Correct source interface.
  • Correct IPsec destination interface.
  • Correct local and remote address objects.
  • Required services are permitted.
  • NAT behavior is intentional.

A tunnel can be fully established while firewall policy or NAT still prevents user traffic.

6. Check firewall sessions

CAUTION 
diagnose sys session list

On a busy firewall this can produce a large amount of output.

What to look for

  • Source and destination IP.
  • Policy ID.
  • Incoming and outgoing interface.
  • NAT translation if applicable.
  • Session state and packet counters.

7. Packet capture

CAUTION

Replace the address with the inside host you are troubleshooting. 

diagnose sniffer packet any 'host 10.10.20.55' 4 0 l

What to look for

  • Does traffic arrive at the FortiGate?
  • Does traffic leave toward the VPN?
  • Does return traffic arrive?
  • Are TCP SYN packets unanswered?
  • Are ICMP responses returning?

8. Advanced IKE debugging

CAUTION

Use advanced debug only when the previous checks are insufficient. Debug output can be very verbose on production firewalls.

Always scope debugging as narrowly as possible and disable it when finished.

Palo Alto IPsec VPN

1. Check overall tunnel state

SAFE 
show running tunnel flow info

What it does

Displays operational information and statistics for VPN tunnel flows.

What to look for

  • Expected tunnel.
  • Tunnel status.
  • Traffic and flow information.

2. Check IKE / Phase 1

SAFE 
show vpn ike-sa

What it does

Displays IKE Phase 1 security associations.

For a specific gateway 

show vpn ike-sa gateway <gateway-name>

If Phase 1 is down

  • Verify peer reachability.
  • Verify pre-shared key or certificates.
  • Verify IKE version.
  • Compare encryption and authentication algorithms.
  • Compare Diffie-Hellman group.
  • Verify UDP 500/4500 connectivity where applicable.

3. Check Phase 2 / IPsec SA

SAFE 
show vpn ipsec-sa

What it does

Displays IPsec Phase 2 security associations.

What to look for

  • Expected tunnel.
  • Active security associations.
  • Correct proxy IDs where used.
  • Matching Phase 2 parameters.

4. Check VPN counters

SAFE 
show vpn flow

What to look for

Look for traffic counters and evidence that encrypted/decrypted traffic is increasing while you generate test traffic.

5. Verify routing

SAFE 
show routing route

What to verify

Confirm the remote network uses the correct tunnel interface and virtual router.

Also confirm the remote VPN peer has a return route to your local network.

6. Check sessions

CAUTION 
show session all

This can produce significant output on a busy firewall.

Look for

  • Source address.
  • Destination address.
  • Application.
  • Security rule.
  • NAT translation.
  • Ingress and egress interfaces.
  • Session state.

7. Check security and NAT policy

SAFE

Verify the traffic matches the expected security policy and NAT policy.

An established VPN tunnel does not automatically mean user traffic is allowed through the firewall.

8. Trigger negotiation when required

CAUTION

Palo Alto provides operational test commands that can initiate VPN negotiation. Use these intentionally during troubleshooting. 

test vpn ike-sa gateway <gateway-name>
test vpn ipsec-sa tunnel <tunnel-name>

Use this when you need to deliberately initiate Phase 1 or Phase 2 negotiation rather than waiting for interesting traffic.

Key troubleshooting principle 

Phase 1 UP
does not mean

Phase 2 UP

and

Phase 2 UP
does not mean

Application traffic works

Treat VPN troubleshooting as separate layers: IKE negotiation, IPsec security associations, routing, security policy, NAT, session creation, and actual packet flow.
